一、Ollama 部署方案

需求：本地 LLM 根据转写文本生成结构化中文纪要，不依赖云端 API，分发体积可控。
方案 A — 内置 Ollama CPU 推理 放弃
将 Ollama CPU 运行时打包进项目。 问题：qwen2.5:1.5b 在无 GPU 机器上生成一份纪要需 30–60 秒，体验不可接受。
方案 B — 内置 Ollama GPU 推理（CUDA） 放弃
同上但启用 GPU 加速。 问题：CUDA 运行时约 1.9GB，分发包臃肿，且 CUDA 版本与用户驱动兼容性难保证。
方案 C — 手写 LLM Runtime 放弃
自实现 GGUF 加载 + llama.cpp backend。 问题：GPU 算子手写不现实，社区 Go binding 成熟度有限，维护成本太高。
方案 D — 完全外包给 Ollama Setup 客户端 最终采用
做法：程序不内置 LLM 运行时，仅通过 HTTP API 调用户本机 Ollama 服务。
  • 零额外体积 — Ollama 由用户决定是否启用 GPU，与本项目解耦
  • 模型首次使用自动从 hf-mirror 下载 GGUF 并导入
  • 用户可自行替换更强大的模型（如 qwen2.5:7b）
代价：用户需安装 Ollama（StartupCmd.txt 给出完整安装引导）。

二、语音识别引擎选择

需求：将录音 WAV 转为带时间戳的分段文本（Segments），支持中文，本地运行。
方案 A — Fun-ASR-Nano-2512（PyTorch） 放弃
阿里达摩院中文 ASR 模型。准确率高，但依赖 PyTorch 运行时， Python 环境管理对终端用户不友好，需 GPU 才能实时推演。
方案 B — Fun-ASR via Docker 放弃
镜像约 16GB，需 WSL2，完全不适用于桌面分发。
方案 C — whisper.cpp 最终采用
做法：whisper-cli.exe + GGUF 模型，Go 通过 os/exec 调用并解析 JSON。
  • 单一可执行文件 + 单模型文件，q5_0 量化后仅 ~548MB
  • CPU 推理可用，GPU（CUDA 12.4）性能更强
  • init-engine 支持按需下载 cpu / blas / cuda-11.8 / cuda-12.4 四个变体
  • 选用 ggml-large-v3-turbo-q5_0，中文识别准确率满足会议场景

三、语音录制方案选择

需求：Windows 上同时录制麦克风 + 系统声音（捕获远程会议对方语音），输出文件供 ASR。
方案 A — ffmpeg + dshow 采集 被替代
曾评估。通过外部 ffmpeg 进程调用 DirectShow 采集音频并编码落盘，属于比较基础的 Windows 音频采集方案。
  • 优点：实现简单直接，amix 滤镜可一步完成混音
  • 痛点 ①：增加 ffmpeg 外部依赖
  • 痛点 ②：dshow 设备枚举不如 WASAPI 完整，设备名与系统面板不一致
  • 痛点 ③：系统音频采集需用户手动在控制面板启用"立体声混音"
  • 痛点 ③：ffmpeg 进程生命周期管理引入额外复杂度
方案 B — WASAPI 原生采集 + 纯 Go PCM 混音 最终采用
做法：go-wca 直接对接 WASAPI，麦克风和系统音频各自独立采集为临时 WAV， 停止后在 Go 内完成 int16 加法混音 + 钳位，输出 16-bit PCM WAV。
  • OBS、Bandicam、哔哩哔哩直播姬等成熟软件均采用 WASAPI，方案成熟可靠
  • 零外部依赖 — 无需 ffmpeg、无需立体声混音
  • WASAPI 回环采集可直接捕获任意播放端点，用户无需配置
  • 设备名与 Windows 声音设置面板一致，选择直观
代价：WAV 文件体积约 10MB/分钟（vs MP3 的 1MB/分钟）， 但对会议录音场景影响可控。

四、Agent 流水线框架选择

需求：将"预处理 → 识别 → 总结 → 输出"串联为可复用的处理流水线。
CloudWeGo Eino compose.Graph 采用
字节跳动 Go Agent 框架，以 Lambda Node + Edge 构建 DAG。当前仅线性四节点， Eino 的能力有余量，但为后续扩展（多模型投票、人工修正节点）预留空间。 对比手写串行调用更利于长期维护。

五、总结

核心原则：同等能力下优先减少外部依赖数量。 每少一个需用户手动安装的依赖，就少一个"我这为什么跑不起来"的支持问题。
模块最终方案外部依赖
LLM 总结Ollama HTTP API（用户自行安装）1
语音识别whisper.cpp（项目内嵌引擎 + 模型）0
音频录制WASAPI（Windows 原生 API，纯 Go）0
Agent 框架CloudWeGo Eino（Go Module）0

用户侧只需安装 Ollama 一个外部软件，其余全部由项目自包含。
